## User-facing change (no change to source processing)

`PhotoEditorModel.checkOriginalMetalHardware()` now runs `OriginalNegativePrintChainParity.evaluate()` **on the iPhone**, after the existing eight native checks and the standalone positive-film RGB appendix. The 8/8 count is not changed; this is an additional diagnostic appendix with its own verdict. Embedded Python Float64 source data is regenerated by CI before XcodeGen creates the iPhoneOS app.

The app prints **all seven stages** and worst-case source-vs-Swift values from 18 developed-negative CMY vectors: negative spectral print RAW, paper logE, absolute 256-point s023 CDF H-D CMY, paper CIE XYZ, linear sRGB, ACES RGC and display-encoded sRGB. It reports MAE, RMSE, maximum and >0.002 count for all 54 channels per stage. If **any stage** exceeds 0.002, the appendix says **未通过** rather than pretending 8/8 certifies RGB. A missing reference/exception says **无法完成**. The main eight tests remain independent.

## Scope boundaries

This evidence executes on the Apple A15 using the **same Swift optical H-D/scanner stage functions as native production**, with source Python references compiled into the build. It is not a Metal GPU texture-image probe for RGB (the colour stage is native Swift), not a live-camera RAW test, not a test of the user's imported photograph, and not complete negative exposure→DIR→grain→paper→JPEG full-image parity. The print input is already-developed CMY, the original enlarger is tested with source source-ACES scanning and disabled B/W reference; the randomized Numba threads and full Float64 rendering remain uncertified.

Test steps: install and sign the **new experimental v1.8.13 Build 38** (unsigned test IPA needs signing); open the app, find `原版 Metal 检测`, run its existing full diagnostic and copy the report. The expected additional header is `附录【原版负片→相纸 H-D→RGB · 本机数值对照｜通过，不计入 8/8 认证】` **only if** 0/54 exceeds the limit across every one of the seven intermediate stages. The newly reported Apple A15 values must be supplied to accept device parity; previous v1.8.12 8/8 alone does not verify this appendix.

The original 256-point fitted source paper H-D production path, scanner, UI wheel, float-preview, per-slider numeric reset, full-resolution Photos/Files export and iOS minimum 16.5 are unchanged.
