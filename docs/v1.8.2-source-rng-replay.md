# v1.8.2 原版随机数与整图密度对照：严格范围

源码以同仓库 \`src/spektrafilm/model/grain.py\`、
\`src/spektrafilm/utils/fast_stats.py\` 和
\`src/spektrafilm/utils/fast_gaussian_filter.py\` 为唯一依据。

## 本轮实际移植内容

1. **NumPy legacy MT19937 基础位流**：Swift \`OriginalSourceMT19937\` 实现原始 624 状态的 32-bit Mersenne Twister，以及 \`RandomState.random_sample\` 的 53-bit Float64 组合。原版 NumPy 自动生成 4 个种子、每个 660 个 UInt32 + 40 个 Float64 对照向量，要求整数完全相同、Double 的 \`bitPattern\` 完全相同。该模块仍未接入生产颗粒链。
2. **原版九路 SciPy 颗粒场回放**：\`generate_source_replay.py\` 从**未修改的原版 AST**执行 \`layer_particle_model\`，按照原版亚层／颜色调用次序与 \`np.random.seed(ch+10*sl)\` 得到九路未模糊颗粒密度。以冻结数据代替生产随机数输入，再用真实 Metal 生产 FIR/YVV、逐层累加、微结构乘法和最终 0.65px 模糊重放，计算逐像素误差。
3. **微结构隔离**：原版 \`fast_lognormal_from_mean_std\` 运行于 Numba 的独立线程随机状态，不能直接用 NumPy/SciPy 的 \`np.random.seed\` 表示其序列。第二幅回放图明确使用被冻结的对数正态输入，只测试原版微结构模糊及乘法顺序，**不把这视为 Numba RNG 逐像素对齐**。
4. **两个源基准**：9µm（真实 SciPy 种子与原版完整路径，可直接复核）和 0.4µm（大染料云 IIR 与微结构激活；冻结微结构随机场）。每个测试输出 MAE、RMSE、最大绝对误差。GPU 容差为 \`abs_error <= 0.002 + 0.001*abs(source_value)\`，是暂定的 Float32 测试门槛，**不是 64-bit 数值等价认证**。
5. **真机自检**：「密度颗粒 → 实测三乳剂亚层 → 原版 Metal 显影链 → 检测本机 Metal 显影内核」新增回放检查与 MT19937 位流检查。Intel macOS CI GPU 曾出现 shader 输出全零；所有相关 GPU 测试必须保留失败结果，不能伪装通过。

## 仍未实现，不可宣称完全移植

- SciPy \`poisson.rvs\`、\`binom.rvs\` 的具体抽样算法和**两阶段种子数组顺序**尚未按 NumPy RandomState 逐抽样对齐。数学上分布等价的 Poisson thinning 仍不是同序随机数。
- Numba \`fast_lognormal_from_mean_std\` 的线程 RNG 与调用顺序尚未移植。
- Metal Float32 的 FIR、IIR、混合、累加路径不是上游 Numba/NumPy Float64 的逐位一致实现。
- 全尺寸真实 RAW 的 Python 光学密度与 iPhone 导出 RGB/纸张/扫描数值对照、DeltaE、拼缝、色域验证仍需同一源片／胶卷／相纸／种子及 GPU 中间值。
- iOS16.5.1 实机导出通过只证明该照片与设置没有触发失败，不能替代算法证据。
