# SpektraFilm iOS v1.8.10 — original NaN scanner wavelength semantics

The upstream source in `src/spektrafilm/model/develop.py` computes spectral
absorbance with NumPy `contract('ijk, lk->ijl', density_cmy, channel_density)`.
A missing sample in ANY of three dye channels (or paper/film base) is NaN;
even NaN multiplied by zero is NaN. Upstream
`src/spektrafilm/utils/conversions.py:density_to_light` then writes ZERO
transmitted light for this wavelength. This is not zero absorbance.

Prior iOS `generate_spectral_data.py` intentionally packed missing measured
arrays as Float32 zero, losing this semantic distinction. The native scanner
then spuriously included visible light at absent wavelengths. In v1.8.9 the
Provia 100F source contains 42 missing dye channels and Velvia 100 contains
56; this explains a concrete source-model divergence that had wrongly been
attributed to Float32 rounding.

v1.8.10 generates an independent 81-byte validity mask per original profile,
decoded with explicit validation in `SpectralPhysics.Profile`; 
`scanPhysicalXYZ` skips any wavelength with an invalid dye/base sample,
in both direct reversal scans and original print scanner routes. This is
source-accurate mathematical behavior, **not** an image-space heuristic.
Other exposure, emulsion, grain and export data keep their existing packing
and UI behavior; no result is silently approximated on missing masks.

`ios/tests/SpectralValidation.swift` now checks original missing-spectrum
profile masks and requires **0/72** source direct-positive scanned channels
to exceed 0.002 absolute sRGB error. Each RGB stage and error remains
reported and separate from the on-device 8/8 hardware tests.

Scope caveats: only the measured-dye scanner semantics are fixed; not source
Numba threaded RNG, full RAW→negative→paper→RGB, full-image float precision,
JPEG, or device v1.8.10 recertification. CI virtual Metal failure must never
be hidden to claim source certification. Experimental unsigned IPA only.

User-provided real-device baseline: v1.8.9 Apple A15 Metal 8/8 passed;
switching/edit/export and Photos save worked. Those measurements are not
automatically v1.8.10 proof.
