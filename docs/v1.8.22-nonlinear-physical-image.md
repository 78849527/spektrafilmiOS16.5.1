# SpektraFilm iOS 16.5.1 — v1.8.22 Build 47 (source nonlinear whole-image)

## True new production port (multi-module batch)

The previously validated v1.8.21 direct ImageIO→Double optical-LUT FIR/YVV
mode remains unchanged and is still the default when 8-bit source IO is
enabled. This version adds a second, **explicitly opt-in** switch
`逐像素全光学（实验）`.

For tagged opaque **8-bit sRGB** image input only, the new path executes
*for each original pixel*, rather than sampling a 3D optical lookup cube:

1. Actual original **Hanatos 2025** film-aware camera spectral response from
   source-bundled Float64 TC LUT, and camera EV before log10;
2. Source **measured film initial H-D**, donor-to-receiver DIR coupling (and
   negative versus reversal silver convention);
3. Source 20μm Gaussian + 200μm exponential mixture at the correct image
   pixel scale, using source **reflect FIR** for sigma below 3 and true
   **Young–van Vliet 2D IIR** for sigma >=3, in CPU Float64;
4. Original **pre-DIR corrected film H-D**, evaluated at the actual corrected
   log10 exposure of every pixel; no approximate RGB 3D LUT;
5. For negative films, true **81-wavelength original dichroic spectral
   enlarger + original s023 three-sublayer paper H-D** with preflash,
   CMY shifts, paper EV and original exposure reference settings;
6. Original **XYZ→linear sRGB→optional source ACES RGC→sRGB CCTF scanning**,
   executed for every original image pixel, with zero-light handling at
   invalid source wavelengths and separate direct-positive scanning;
7. Explicit ImageIO RGBA8 input and direct JPEG output, no CoreImage pixel
   intermediate, no automatic resolution change and no fallback to fast LUT.

The original source has more physical stages than this tested scope. Exact
mode requires original scanner ACES, Hanatos Float64, original source DIR
and negative source printing; it refuses unverified CAM16/black-white/photo
exposure-reference mode and stochastic grain/halation/scanner finishing
rather than silently simulating them with an unrelated algorithm.

## Performance / safety

The full optical mode is CPU- and memory-heavy on iOS16.5.1. To prevent
unsafe large-image allocations, this experimental path **explicitly refuses
original-resolution images larger than 2,000,000 pixels**. It uses at most
640px preview dimension, and does NOT silently downscale a full JPEG export.
The previously user-approved v1.8.21 source DIR mode remains separately
selectable for large original-resolution outputs. A larger memory-safe
whole-image implementation is a future task, not claimed done.

## Upstream Python whole-image reference, not synthetic identity LUT

The new `generate_source_physical_frame.py` imports and executes actual
upstream original Hanatos, film density curves, couplers, FIR/YVV,
s023 paper H-D and physical paper scanner on **three nonuniform 2D image
fixtures** from ImageIO-loadable, explicitly tagged-sRGB 8-bit PNG.
Two camera/film stocks, two printing media, paper curve morph (including
developer exhaustion), two camera EV variations, paper EV variations,
non-neutral CMY dichroics and preflash are covered.

Seven original Python Float64 whole-image stages are recorded with SHA256:
`logRaw`, `initial`, `inhibitors`, `diffused`, `correctedLog`,
`density`, `printed`. The CI then decodes the image using **the same
production OriginalSourcePixelIO.decode** and runs the **same new production
OriginalSourcePhysicalImage.develop**. For each stage and every channel it
prints MAE, RMSE, max absolute error and worst pixel/channel. A discrepancy
over 0.002 absolute per channel or 0.0003 mean (0.0005 for printed) fails the
build. The test also verifies oversized images are rejected and never routed
back to mobile Float32 LUT.

This is a stronger proof than v1.8.21's source Double optical LUT nodes,
which still interpolate a 3D optical cube. But it remains restricted to the
opt-in 8-bit sRGB, grain-off, optical-scatter-off, source ACES and original
Python fixture conditions.

## Known not-yet-exact / unported

- Source stock spectral and measured film H-D samples in
  `GeneratedSpectralData` are still **Float32 packed**; converting the
  calculations back to Swift Double does not restore the lost Float64 data.
- Numba thread PRNG, 3×3 grain, microstructure random streams and all
  particle-field full-image numerical equivalence remain incomplete.
- Original Hanatos adaptation surface/input optics, lens blur, native RAW,
  ProRAW, 16-bit and Display P3 input are NOT supported by this mode.
- Non-spectral default mobile scanner fallback, true source default CAM16
  gamut, exact white/black reference exposure, physical halation and scanner
  finishing are still outside verified whole-image scope.
- Neither full physical iPhone GPU bit-equivalence nor all-module end-to-end
  original Float64 photographic-pipeline parity is certified.

The CI's `verify_precision_release.py` remains unchanged and fail-closed;
a passing stage-limited test is NEVER a complete original SpektraFilm source
certification. Any unsigned IPA must use `UNVERIFIED-TEST`.

## User regression

On a small (<2MP) opaque tagged-sRGB JPEG/PNG:

1. Enable `Hanatos 原版 Float64`, `扫描光源 · ACES 色域`, original
   enlarger for negative film, `原版 DIR 空间显影`,
   `DIR 原版 FIR/YVV`, `8-bit 原版像素直连` and the new
   `逐像素全光学（实验）` switch; disable grain, halation, CAM16, BW
   reference and scanner finishing.
2. Check floating preview, numerical adjustment reset, paper/film wheels,
   long-press original and original-resolution JPEG export + Photos save.
3. For >2MP images, expect a specific error, no app crash or fast-mode
   fallback; turn OFF the new switch to use the previous high-res direct DIR.
4. Compare same photo with previous v1.8.21: some image differences are
   expected because physical nonlinear per-pixel optics replaces 3D
   interpolation, not because precision thresholds were loosened.
