# SpektraFilm iOS 16.5.1 — v1.8.51 Build76 batch

## User-selected output ceilings (no algorithm downgrade)
- Intelligent safe output **up to 12,000,000 pixels**. Economy output **up to 7,200,000 pixels**; smaller inputs retain their original width and height. Both preserve aspect ratio and present the actual dimensions in the existing explicit user confirmation sheet.
- These are **ceilings**, not unconditional guaranteed sizes. The underlying conservative live-process-memory budget, 50% safe / 30% economy allocation allowance, 1.5 GB maximum heuristic and original + source grain per-pixel estimates remain unchanged. Insufficient headroom may produce smaller *confirmed* output geometry, never an undiscussed secondary shrink or an automatic algorithm fallback.
- The 13MP original source preflight remains unchanged. True full original optical+grain works in Float64 and can exceed A15 headroom at 12MP: 120+272 bytes/pixel means roughly 4.7 GB estimated for 12MP before other optional modules, therefore it is **not** accurate to promise a 12MP grain-rendering result on that phone. Real captured memory usage is not certified. No budget percentages are raised to manufacture a larger displayed resolution.
- The raw original full-size option remains unchanged, and the explicit safe/economy user choice remains the sole resize authorization.

## Batch 2: exact source three-sublayer grain interpolation, CPU efficiency
- Retain `src/spektrafilm/utils/fast_interp.py` (source Python) as the authoritative algorithm, including the **non-monotonic source** H-D axis and `np.searchsorted(axis, x, side='right')` over [0,256), signed unclipped layer densities, exact Double reciprocal interpolation and end-point semantics.
- Previously `SpectralPhysics.sourceSpatialGrainLayers` performed **nine** identical binary searches per pixel (one search for each of the three sublayers × three channels), also reconstructing the 256-value axis from source curves repeatedly.
- Build76 **precomputes the three Float64 axes and nine density curves once per frame**, and performs a single original search for each of the three colour channels. The three measured layer samples are computed for the same right-biased interval and written into a reusable nine-value scratch array.
- `OriginalSourcePhysicalGrain.apply` now reuses its 3-channel CMY input and 9-value layer scratch for each pixel. Legacy test adapters can still supply the former `sublayers` interface; full source production uses the new `sublayersInto` interface. Existing reuse of 9-layer SciPy rates/probabilities/saturations/dye-cloud buffers is unchanged.
- **No statistical/per-pixel/time-speedup percentage is claimed without A15 profiling.** Independent Python source whole-image stage test retains its existing 1e-8 maximum and 1e-10 MAE for all nine source layer channels; downstream optical RGB remains independently compared. SciPy/Numba random sequence, blur, boundaries, Float64/Float16 separation and source profile data are not changed.

## Batch 3: 13MP source scanner geometry alignment
- The optional **original Double scanner lens Gaussian/unsharp** `OriginalSourceScannerOptics.applyInPlace` previously rejected source files over 12MP, even though ingress supports 13MP. The scanner geometry guard is now aligned to 13MP, with the existing width/height and full-memory checks preserved.
- This is source path capacity alignment; do not infer 13MP memory safety from metadata acceptance. Full original image scanner timing and visual output need on-device testing.

## Regression, build and certification boundary
- Build once after all source edits, scripts, tests, docs and CI changes are committed. The new version branch is `ios16.5.1/batch-source-efficiency-12mp-7p2mp-v1.8.51`; code and test reference the same SHA.
- Run source full-image independent Python→Swift original grain→optical RGB, strict H-D sublayer input, source scanner optical tests, safe/economy geometry tests, iPhoneOS Release build, iOS16.5 minimum identity, and unsigned experimental IPA creation.
