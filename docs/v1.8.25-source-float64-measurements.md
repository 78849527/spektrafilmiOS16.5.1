## Batch of ORIGINAL source algorithm inputs now carried in Float64

The previously user-tested physical optical chain computed in Swift Double
but some measured profile values were previously rounded to **Float32
before** the Swift calculation. Converting those rounded numbers back to
Double could never restore the source measurement bits.

v1.8.25 adds and directly consumes **separate source Float64 arrays** while
retaining all mobile Float32 arrays and their exact old bytes:

1. **28 measured materials** (20 camera films: 16 negative + 4 reversal;
   6 paper + 2 motion-picture print stocks): original 81-wavelength
   log sensitivity (81×3), CMY dye absorbance (81×3), substrate base
   density (81), 256 log-exposure nodes and 256×3 H-D densities.
2. **20 original 3×3×256 emulsion/sub-layer density arrays** separately
   encoded in IEEE 754 Float64, independently of fast Float32 grain
   profiles. Existing null/NaN masks remain untouched and determine zero
   transmitted light at absent wavelengths.
3. **20 original Float64 pre-DIR corrected density H-D curves**, from the
   source's donor/receiver coupling matrix and original measured H-D.
   Source film interpolation uses full Float64 abscissae and ordinates.
4. **Original three-layer s023 paper H-D source exposure nodes** now use
   unrounded original Float64; the legacy mobile `prepareSource([Float])`
   overload remains available and unchanged.
5. **Full spectral optical constants in binary64**: Mallett sRGB basis,
   normalized D55/D50/K75P illuminants, CIE1931 2° response, original
   unfiltered TH-KG3 light source, Schott KG3, default dichroic spectral
   transmittance, and 128 original stock/media neutral CMY spectrum pairs.
   For opt-in physical source, 81-wavelength XYZ/ACES integration uses
   these Double constants, source profile Double sensitivity and dyes,
   not Float32. Fast mode continues using original packed Float32.

No file is quietly converted at runtime: the source mode's profile
constructor hard-errors on missing/malformed Float64 fields. The
`OriginalSourcePhysicalImage.Parameters.createEngine()` explicitly selects
`sourceMeasuredFloat64:true`, while other existing `SpectralPhysics`
callers default to `false` and retain the original mobile path.

exact optical lens halation, original RAW/ProRAW/16-bit/P3 and scanner
CAM16 complete image workflow; native iPhone GPU full-image Float64 parity.

correct pixel colors; retain the original strict certification rejection.
