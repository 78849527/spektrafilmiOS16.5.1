# v1.8.6 — 原始分辨率与安全输出分辨率并存

需求：v1.8.5 在 A15 上对普通分辨率照片能够完成源 SciPy 两阶段抽样和导出，大分辨率因内存预算而失败。**不能**为保证出图偷偷重置随机数、牺牲精度或替换原版算法；新增用户明确选择的安全输出尺寸。

## 交互与保证

现有顶部 **保存相册** 和 **分享/存储文件** 两个按钮位置、图标不变。点击时显示两项：

- 原始分辨率（不缩小）：保留 v1.8.5 的原尺寸高质量 JPEG 98%，即使失败也明确报错，绝不静默缩小。
- 安全分辨率（最高 300 万像素）：由设备物理内存再计算收紧的整图尺寸，保持原图宽高比。先用 Core Image Lanczos 等比例缩小整张输入，再交给现有完整的胶片曝光、三乳剂 SciPy 顺序 Poisson→Binomial、Metal FIR/YVV、纸张与扫描处理。不是渲染大图后降采样，也不对 512 像素块独立重置种子。若照片本身尺寸低于限制，保留原尺寸。实际导出尺寸写入状态栏；相册保存与文件分享使用同一 JPEG 98%。

算法规则：像素上限 3,000,000，同时要求估算占用（104 字节/像素）不超过 min(1.5GB, 设备物理 RAM / 3) 的 30%。内存估算是 **保守启发式，不是万无一失的 iOS jetsam 保证**。若 GPU/系统内存仍不足，明确提示错误；不得自动回退到其他渲染算法。

## 原版认证边界

选用安全分辨率会让像素大小、颗粒密度、随机数消费次数随**明确选定的新尺寸**重新计算；它不是“原始尺寸胶片结果的等比例拷贝”。对该输出尺寸，仍按原版完整图片、每通道每亚层先全图 Poisson 再全图 Binomial 的顺序采样。上游 Numba 微结构 RNG、全部 Float64 中间过程、RAW→纸张→RGB 完整逐像素一致性仍未完成，因此 v1.8.6 继续标记 UNVERIFIED-TEST。

## iPhone 实机验收

1. 同一大图：原始分辨率导出如仍达不到物理预算，应继续给出清楚错误；**安全分辨率**应生成最高约 3MP 的 JPEG 并保存相册。
2. 通过顶部分享图标也选择安全分辨率，确认能存储到文件、输出尺寸与状态栏报告一致。
3. 保留悬浮照片预览、左右双拨轮、滑块数值恢复默认、6→7 项硬件自检与普通分辨率原版 SciPy 渲染。
4. 运行 CI RAM-safe 输出几何纯 Swift 测试，并保持原有胶片、相纸、Core Image、Metal、光谱回归。

**注意：不要把本次修改标成原版整图 Float64 数值认证。**
