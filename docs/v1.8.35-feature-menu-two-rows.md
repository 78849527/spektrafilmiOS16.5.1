# SpektraFilm v1.8.35 Build 60 — two-row direct feature navigation

## User-requested layout (clarified)

The adjustment panel is no longer a compact-switch row followed by a
redundant category row (基础 / 扫描 / 印相 / 光学 / DIR / 颗粒).
It has exactly TWO top rows, and a lower parameter region.

1. **First horizontal row — features WITH submenus or controls:**
   基础, 扫描, 锐化, 放大机, 预闪, s023, 光晕, DIR, 颗粒.
   - 基础 has no on/off state. Tap its label to expose original film/paper
     exposure controls and LUT strength directly.
   - For every on/off feature, tapping the title turns it ON if necessary
     and opens its OWN submenu immediately; tapping an already-enabled
     title selects its controls without disabling it.
   - The mini 28x16 toggle on the same chip explicitly toggles the
     function. Turning it OFF immediately removes its submenu.
   - No feature panel is visible when its own switch is OFF; downstream
     options retain all upstream guard conditions.
   - 预闪 is now direct, NOT buried under 印相. The enlarger must first
     be enabled for preflash to become actionable; source optical
     semantics and ordering remain unchanged.

2. **Second horizontal row — switches with NO own submenus:**
   64位 Hanatos, 乳剂散射, plus context-dependent CAM16, 按印相曝光参考,
   印相归一化, 拍摄曝光补偿, SciPy source RNG, 离散 Poisson.
   They are displayed only when their respective parent setting path
   is active. A switch is an on/off operation; double tapping restores
   the original Boolean default, including TRUE for print exposure
   normalization / shot-exposure compensation. No third category
   selection row exists.

3. **Lower content region:** only the parameters of the feature last
   selected in row one, and only while enabled. In particular the
   printed CMY values, original preflash exposure/M/Y, s023 H-D paper
   curves, scanner calibration, halation strength, original spatial DIR,
   8-bit physical source pathway, and grain/Metal diagnostics remain.
   Child options that have descendants remain in their parent submenu.

## Confirmed-rule interaction protocol (same v1.8.35 branch)

Only requirements verified from existing SourcePixelIO/source physical
validators are encoded as persistent mutual exclusion constraints.
When selecting pixel-direct or full-physical modes, the UI first computes
all already-enabled settings that must change. If there are any,
a modal alert lists each change and requires **explicit confirmation**;
Cancel preserves the user's settings. With no changes required, switching
mode proceeds directly. Entering direct pixel mode disables grain, old CI
scanner finishing and incompatible old scatter/halation; entering full
physical mode enables Hanatos Float64 and source ACES scanner, enables
the source optical print on negative film, and disables CAM16, black/
white field and exposure-reference modes. Physical mode retains the
source Double scatter/halation, not the old CI effects.

Confirmed incompatible switches are disabled/grey, with VoiceOver hints
stating the original algorithm requirement. After leaving pixel-direct
mode, they become selectable again. In particular, parent DIR FIR/YVV
cannot be switched off while pixel-direct depends on it, and the negative
source enlarger cannot be switched off while full physical depends on it.

**Do not encode unverified limitations as permanent hard rules.** For
future unconfirmed or experimental restrictions, show a descriptive
confirmation prompt and leave the existing algorithm validators as the
single source of truth until the rule is proven and approved. Preserve
original/fast mode separation and never silently downgrade.

### Disabling a mode also checks dependencies

Turning pixel-direct OFF while physical mode is active requires user
confirmation because it will switch the dependent physical mode OFF.
Turning full physical OFF while ordinary direct-DIR would retain enabled
scatter/halation requires user confirmation to disable these unsupported
options first. Without conflicts the mode closes immediately. The original
per-mode renderer guards remain in force.
