# SpektraFilm iOS v1.8.11 — negative optical printing and print-medium scanner stages

Parent: iOS 16.5.1 v1.8.10, physical A15 8/8 validated by user. Parent source positive-scan 24 × 3 numerical parity: max encoded sRGB error 1.98986792023792e-05, 0/72 beyond 0.002. **This hardware status does not automatically carry to v1.8.11.**

## Source discrepancy fixed

Original `src/spektrafilm/runtime/stages/printing.py:PrintingStage._film_cmy_to_print_log_raw` calls
`compute_density_spectral` on measured CMY negative dyes and film base, then `density_to_light`, which zeros transmitted light where spectral density is NaN. An unavailable dye measurement at a wavelength causes the **whole wavelength's light contribution to be zero**, including when that channel's input density is zero (`NaN * 0 = NaN`). Prior Swift `SpectralPhysics.printRaw` packed null dye absorption as Float32 zero and erroneously let that wavelength through into paper exposure.

v1.8.11 uses the already source-derived 81-wavelength mask for each of 28 original measured media to skip those invalid wavelengths in the **production** negative-to-paper `printRaw` integration. This applies in normal rendering and reference exposure computation, without silently substituting a heuristic.

## Two independent stage-scoped proofs

1. **Negative CMY -> optical print exposure:** `generate_print_optics.py` now uses original Python NaN semantics *before* applying light-transmission zeroing; replaces the old null-to-clear-film reference vectors. Six film/printing-medium/filter/preflash/exposure scenarios are compared with native Float32 spectra in `PrintOpticsValidation.swift` for optical irradiance, per-paper-channel raw exposure, source normalization modes, preflash, and log exposure. The Python generator also asserts that the previous null-as-zero implementation demonstrably produces different raw results.
2. **Already-developed print CMY -> scanning XYZ -> ACES/sRGB:** Independent Python source functions generate 24 cases: 8 printing media × 3 in-gamut optical-density states, including D50 paper and K75P motion print stocks. Swift `directPrintScannerStages` exercises the same production scanning routines but bypasses film/paper H-D. `OriginalPrintScannerParity` reports per-stage MAE/RMSE/max and the CI regression refuses output sRGB errors >0.002.

**These two proofs do NOT constitute a certified contiguous negative -> paper H-D -> scanner RGB chain**: the Python source uses `develop_print_morph` fitted CDF model for print development and may apply exposure calibration, diffusion, glare, black-white reference and default CAM16 gamut compression. Existing mobile H-D curve/morph pipeline is not yet proven float/order-exact for full output. No full RAW, stochastic Numba thread RNG, or image/JPEG pixel parity is claimed.
