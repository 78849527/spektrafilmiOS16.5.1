# v1.8.9 — 分段原版扫描 RGB 对照与 Metal 输出探针

基线：v1.8.8 `56312700a3f84a2ac0e87375892d2215fbf4c502`。原版优先，不改变生产扫描或颗粒数学模型。

## 原版正片直扫：四阶段误差

Python `generate_source_rgb_parity.py` 从上游源码继续提取原版光谱计算与 ACES RGC 变换，并对 24 个样本生成：
1. 光学密度积分后的 XYZ；
2. `colour.XYZ_to_RGB` 的线性 sRGB；
3. 原版 `compress_rgb_aces_rgc` 之后的线性 RGB；
4. 原版 CCTF 编码之后的 sRGB。

Swift 的 `SpectralPhysics.directPositiveScannerStages` 重用 **当前生产扫描函数**，对每阶段计算 MAE、RMSE、最大绝对误差、超限通道数和最大误差位置。这样后续可定位最早偏差阶段，避免把后级错误误判为前级错误。独立生产 `scanFilmDensity` 与诊断输出必须一致，不一致直接报错。

**注意：** 上述原版证据不等于整体 Python→iOS 数值等价；原版默认 CAM16、负片相纸、RAW、颗粒随机数、最终 JPEG 均未在本阶段认证。采样阈值 0.002 只作偏差观测，不被用来自动通过认证。

## Metal 测试环境判别

在原有 reflect FIR 纹理/参数探针之前，增加独立 `originalFilmDebugWriteConstant`，GPU 把指定常量写入 RGBA32Float 纹理。若 GPU 读回仍为零，说明连常量写入都失败，当前 CI 无权判定“卷积算法不等价”；CI 保持失败并报告设备和常量读回值。若常量成功而原有探针失败，再检查纹理绑定 / Swift-Metal ABI。

本版本不更改原版颗粒显影内核、YVV 系数、随机数模型，也不改变悬浮预览、两个拨轮、复原及相册高清导出。所有 IPA 都必须标注未签名、未完成实机及整图认证。
