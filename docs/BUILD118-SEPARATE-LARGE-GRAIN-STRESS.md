# Build118｜8MP / 10MP / 13MP 独立大图验收及内存生命周期预算

## 已确认基线（Build117 真机）
- 6MP SciPy 实测 RSS 775,569,408 字节；Numba 四线程 835,715,072 字节；两条路线真正完成完整 Float64 光学颗粒渲染。
- Build117 八尺寸×双路线共 10 项实渲染、6 项被准入拒绝，0 项真实渲染失败。8/10/13MP 当时尚未实际运行。
- 当时进程可分配约 3.189GB，动态 80% 准入约 2.551GB。此前账本 8MP 2.688/3.136GB；10MP 3.36/3.92GB；13MP 4.368/5.096GB。

## Build118 实际变更
1. **三个不同按钮**：8MP(4000×2000)、10MP(4000×2500)、13MP(5000×2600)，每次仅处理选择的这个尺寸。每次两条路线：原版 SciPy 固定粒子种子，及原版可选 Numba 四线程 fast_stats（非逐位等价保证）。
2. **按阶段核算的基本颗粒账本**：基本无额外光学/FFT/扫描/印相扩散、无保留整图诊断快照的三亚层原版链路，按源 RGB/已测输入、积累输出、三层插值、粒子概率与率、染料云缓冲、粒子缓存等同时共存的字段，估计 SciPy 176B/像素、Numba 184B/像素。均包含分配/CoW 保守余量；比 6MP RSS 实测更保守，但不是 13MP 瞬时峰值证据。源业务和测试都执行相同账本；其他复杂功能组合保持 Build106 原账本。
3. **内存准入仍是 iOS 当前可分配内存的 80%**；获取不到真实数据时使用物理内存 1/3 的兜底。仍执行 13MP 最大尺寸和 512MB FFT 源保护。不得缩图、禁用颗粒、切换 GPU Float32 或静默降级。
4. **采样报告独立**：各尺寸对应 `Build118-{size}MP-grain-memory-*.json/.log`，记录两路线真实 RSS（25ms 周期采样）、执行时长、输出指纹、内存预算与阶段 RSS 快照。报告仅代表合成 sRGB 源真实物理链路，不代表 RAW/ICC、Python 原版完整 RGB 图像逐像素一致性。
5. **闪退恢复**：分别保存 `Build118-last-8MP-checkpoint.txt` / `10MP` / `13MP`，每阶段更新原子检查点。设备若被 Jetsam，保留最后完成的阶段与路线以定位。
6. 保留 Build116 一键 16 项矩阵，并复用新版统一内存账本。为防止重复申请巨大内存，请分别启动 8、10、13MP，不自动连续进行三个尺寸。
