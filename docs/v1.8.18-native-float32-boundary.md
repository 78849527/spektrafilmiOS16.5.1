# SpektraFilm iOS v1.8.18 — native Float32 bridge and source DIR Double evidence

## Why
The user's Apple A15 v1.8.17 report measured 1287/1287 Core Image RGBAf
input samples identical to IEEE Float16 rounding. Direct Float32 rounding
was far smaller (max 2.94e-8) than CI ingress (max 2.408854e-4).
Source Python FIR/YVV Double was 5.55e-16, whereas production CIImage DIR→LUT
reached max 3.137166e-4. CI rendering therefore remains **unverified** as a
source-exact input/output transport on iOS 16.5.1.

## Changes
1. Add `originalFilmFloat32Identity` in the real iPhone Metal library.
   It copies rgba32Float texture samples directly in a compute shader without
   Core Image, gamma, or half conversion. Existing 1/8 hardware diagnostic
   now independently verifies every Float32 **bit pattern** for 21 RGBA pixels
   (63 RGB + 21 alpha); any failure aborts the existing 8/8 diagnostic.
2. Add a diagnostic-only `sourceRGBOverride` and raw Double stage observer
   to the **same** production `SourceSpatialDIRConvolution.applyExactImagePath`
   mathematical kernel. The regular app still uses `readRGB(CIImage)`.
3. Source Python 2D reference fixtures (3 images, 1,287 channels) now compare
   seven raw Double production stage arrays before converting to CIImage.
   This removes the CI half-quantization *from the test*, not from the
   application input/output. A failed stage marks the appendix **not passed**.
4. Preserve original FIR/YVV coefficients, ordering, boundary semantics,
   kernel thresholds and 0.002 CI acceptance threshold.
5. Bump bundle to 1.8.18 (Build 43); retain all previous iOS UI/export and
   GPU/NumPy/SciPy evidence tests and original-release certification guard.

## On-device verification
Open photo → right Adjust panel → enable DIR and original FIR/YVV →
enable grain and original Metal emulsion chain → select
"检测本机 Metal 显影内核" and share the full report.

New points to find:
- 1/8 section: `原生 Metal rgba32Float（无 Core Image）` with 63 RGB bitwise
  pass and Double→Float32 maximum input quantization.
- Appendix: seven `Float64 原版数组输入→计算阶段` metrics versus Python
  reference, separately from CIImage production metrics.

**Certification caution:** Even if both new tests pass, the actual
production `PhotoProcessor.decode → SpatialOptics → CIImage → FIR/YVV →
CIImage → JPEG` path still crosses Core Image's iOS half-float working
buffers. No "complete source-exact", "Float64 whole image", "Numba RNG",
RAW or JPEG parity claim is made. Native Float32 texture transport is only
the prerequisite for a future real production bypass. The test IPA is
unsigned and is published only as an experimental prerelease.
