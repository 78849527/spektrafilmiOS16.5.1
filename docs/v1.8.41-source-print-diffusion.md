## New implementation
Opt-in print source mode is available only in original per-pixel full
physical path on NEGATIVE film with original enlarger enabled.
Reuses one native Float64 source diffusion module for both photography
and enlarger, but inserts it at distinct original stage boundaries:

1. Developed film CMY densities after original spatial DIR.
2. Original enlarger per-wavelength paper exposure including filtered
   TH-KG3 / TH-KG3-L light source, neutral CMY, preflash, reference
   exposure, and printing EV.
3. The actual 3-channel **paper photon irradiance** is materialized as
   a full Double RGB frame (instead of immediately developing/scanning
   each pixel).
4. Source original \`apply_diffusion_filter_um\` on this full paper photon
   frame: 4 optical families, warmth per channel, all 6 group overrides,
   original \`reflect\` padding and accurate per-channel Float64 FFT.
5. \`log10(np.fmax(raw,0)+1e-10)\` photonic exposure boundary.
6. Original fitted paper CDF H-D curves, then original XYZ / ACES scanner.
7. Optional source scanning blur/unsharp operates on LINEAR RGB after
   paper developed densities, before CCTF encoding.

The normal (diffusion OFF) path retains the existing single-pass
source original print behavior. Native \`scanFilmDensity\` was refactored
only to share the exact original scanner computation with the new
post-paper-photon developer; no duplicate scanner, extra 3D LUT or
post-scanner fake bloom is introduced.

## Validation
- The real compiled Swift \`OriginalSourceDiffusion.apply\` is compared
  against the exact pinned original Python AST on four 2D RGB frames.
- Also compare the *result after source print log10* per channel against
  Python's \`log10(np.fmax(source_diffused_raw,0.0)+1e-10)\` with strict
  <5e-12 tolerance. Original PSF reflect convolution remains <1e-12.
- CI asserts source order in the REAL production renderer and that the
  same optical print raw formulas feed the separated full-image pass.
- The source physical mode's pre-export pixel and memory guard includes
  the additional optical print full-size buffer, and actual FFT
  workspaces have a strict 512 MB cap. When safe original execution
  is unavailable the app reports an explicit error and never switches to
  mobile Core Image approximation or secretly resizes.
- Passing these stage tests does NOT certify the 12MP original
  RGB/spectral/Numba/Metal overall pipeline or on-device crash
  regression. iOS 16.5.1 support and scientific gates are unchanged.
