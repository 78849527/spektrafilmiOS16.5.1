# SpektraFilm iOS 16.5.1 — v1.8.50 Build75

## Objective
Preserve original full optical precision **and** reduce avoidable CPU allocation costs. All original Python algorithms and the iOS 16.5.1 UI, verified original/fast-mode separation, source memory guard, and unsigned experimental release semantics remain unchanged.

## New independent source image proof
- `ios/scripts/generate_source_physical_frame.py` runs actual source Hanatos camera RGB→RAW, measured film H-D, original 2D FIR/YVV spatial DIR, original film three-sublayer inversion, **pinned unmodified** `src/spektrafilm/model/grain.py::apply_grain_to_density_layers`, source optical enlarger, original source paper H-D and source paper XYZ/ACES/sRGB.
- The original grain.py, fast_stats.py and fast_gaussian_filter.py Git blob hashes are checked before execution. Real SciPy full-plane Poisson→Binomial (9 layers), dye clouds, original Numba one-worker lognormal microstructure and final Gaussian blur are executed in order. Explicit `NUMBA_NUM_THREADS=1`, `NUMBA_THREADING_LAYER=workqueue`, `seed=8888` are mandatory; there is no simulated RNG field.
- The generator writes endian-stable Float64 arrays and SHA256 for `grainSublayers` (9 channels), `grainDyeClouds` (3), `grainMicrostructure` (3), `grainDensity` (3) and `grainPrinted` (3). All are calculated from the same Python input image, not independent disconnected mocks.
- Four image cases: legacy 19×13, 31×17, 47×31, plus a new 12×10 pixelUM=0.35 case that actually activates the Numba lognormal transform. With original pixelUM=4–12, microstructure sigma was below the source activation threshold; only the fourth case certifies the active micro branch.
- `ios/tests/SourcePhysicalImageParity.swift` compares each stage to the SHA256-pinned independently generated original Python image. The new comparator does not use the same Swift print branch as its truth. Existing per-stage max=0.002 and MAE=0.0005 limits remain unchanged; all deviations must be reported, not silently accepted.

## CPU efficiency without changing the model
- `OriginalSourcePhysicalGrain.apply` now reuses three Float64 scalar arrays (rates, probabilities, saturations) and one RGB dye-cloud buffer across nine original SciPy sublayers. Previously each sublayer allocated four full-image temporary arrays. No formula, boundary, source seed, RNG call count, layer order, Fourier/FIR/YVV behavior or output precision is changed.
- If dye-cloud blur is disabled, the 3-channel reusable buffer is not allocated at all.
- This removes repeated large heap allocations, but no unmeasured percentage speedup is claimed. Native A15 performance must be measured on actual photographs separately. The conservative `120 + 272 bytes/pixel` memory guard for opt-in source grain is **not** lowered without a peak memory measurement.
- Default mobile fast mode remains independent and unchanged. An original exact-mode failure cannot switch to Float16/CI or a mobile approximation.

## Claims and exclusions
- **Current code change status**: changes committed; numerical equivalence is claimed only after GitHub's independent Python stages, Swift tests and iPhoneOS compiler pass. A local iPhone 8/8 report is not proof of independent original full RGB.
- After successful verification, the four small source images establish controlled **single-worker** Python original grain→paper→RGB comparison at their tested configurations. They still do **not** establish random-seed-independent multiworker Numba prange, sensor RAW, large-photo Float64 exactness, JPEG byte-level identity, GPU independent native spectral parity or iPhone display color management.
- iOS 16.5.1 and all existing UI controls, safe-memory full-optics output, true original and separate fast algorithms remain hard constraints.
