# Build107｜统一真机反馈 LOG（同时覆盖 Build106 + Build107）

基线：Build106 `3ac12e9d8da154ef133a6e3a0b6881d15d91d1f8`。本轮 App：v1.8.73 / Build107，最低 iOS 16.5。

## App 新入口

高级 → 验证状态与诊断 →「Build106 + 107：一键生成真机反馈 LOG + JSON」。

一次按钮触发同一编译 SHA 的四组检查：
- Build103：4 张 Python 原版小图、28 个 Float64 阶段的逐样本真实差异和首个失败；
- Build104：5 张原版颗粒小图、20 个阶段的逐样本真实差异及单层 SciPy 条件分支；
- **Build106**：1/2/4/7.2/12/13MP × 基础、九层颗粒、全部光学、全部光学＋诊断多阶段，共 **24 个无大图分配的生产内存准入判定**。实际调用 Build91 原版生产内存守卫，并用 Build106 独立账本交叉校验；额外验证低内存确实拒绝及 190 万像素颗粒流程理论提前释放 228MB。
- **Build107**：在真机可分配内存充裕时实际触摸 16MiB 物理页，读取 iOS task_info 驻留内存和 os_proc_available_memory 处理前/中/后快照；不足 256MiB 安全拒绝，不强行触页。

导出一对同 UUID 的 `.log` 与 `.json`，通过系统活动表单**一次同时分享两个文件**。保留原 Build103/104 单独诊断按钮，不强制用户重复操作。

**反馈不是原版完整认证**：13MP 大图仅预算检查、未实际光学渲染，未测真实 13MP Jetsam 峰值；Build106 228MB 是可释放 Float64 数组的生命周期推导，非真机 RSS 实测节省。默认多线程未播种 Numba RNG、RAW/ICC/EXIF/XMP 全链仍不认证。

## 认证顺序

先通过真实 Python 颗粒 20 阶段与 SciPy 36 档，Build106 内存账本、Build107 源码与 iPhoneOS 编译，再发布独立未签名 IPA；最终真机只需导出一次本对 LOG/JSON。
