# v1.8.8 — Python 原版输出 RGB：正片直接扫描数值证据

本阶段不修改通过测试的原图／智能／省内存输出方式，也不替换胶片显影算法。继续完成原版移植中尚缺的 **输出 RGB 数值对照**，从可以明确隔离误差的正片胶片扫描分支开始。

## 比较范围（严格限定）

原版源码：
- `src/spektrafilm/runtime/stages/scanning.py` 的光学密度到 RGB 流程；
- `model/develop.py:compute_density_spectral`；
- `model/illuminants.py:standard_illuminant`；
- `utils/conversions.py:density_to_light`；
- `utils/gamut_compression.py:compress_rgb_aces_rgc`（**源代码提供的可选 ACES 1.3 模式，不是默认 CAM16**）。

Python generator: `ios/scripts/generate_source_rgb_parity.py`，正片 Fujifilm Provia 100F 和 Velvia 100 采用原版 81 点染料光谱 / 底片基底 / D50 光源和 CIE 1931，对 24 组指定 CMY 光学密度执行源函数，输出源 Float64 的线性 RGB 和最终 sRGB CCTF 向量。

Swift: `ios/SpektraFilmPort/OriginalSourceRGBParity.swift`，同一输入交给已接入的 `SpectralPhysics.scanFilmDensity`，并严格要求为正片、选择原版扫描且关闭可选黑白参考校正与 CAM16。计算 72 通道样本的绝对 MAE、RMSE、最大误差、发生最大误差的胶卷/样本/通道、以及误差超过 0.002 sRGB 的通道数。

这个步骤**报告偏差，不会因为编译通过而认定两者相等**；即便偏差高也应如实显示。CI 在原有光谱回归中打印准确指标；真机 Metal 显影自检的现有八项不增加虚假“通过”项，新增“附录：原版 RGB 数值对照”标明实验性。

## 无法从本次对照推出的结论

本比较从**已经给定的三通道胶片密度**开始，未包含相机 RAW／上游 Hanatos 模型、曝光、DIR、随机胶片颗粒、负片放大机滤色、相纸印相、后期杂光/锐化、输出 PNG/JPEG 压缩。也未涵盖原版默认 CAM16 UCS 色域路径。因此，它不是整个 SpektraFilm Python → iOS 最终照片色彩 1:1 的证明。

下一轮需要扩展为负片→相纸→扫描和固定整幅输入，同时逐步追查 Float64→Float32 差异和真实设备输出。原版 Numba 并行 PRNG 还未完成。保留既有 iOS 16.5.1、悬浮预览、双拨轮、滑块恢复、高清和相册输出，并继续以未认证测试版发布。
