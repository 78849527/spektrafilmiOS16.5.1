# v1.8.15 · Build 40 — bundled Hanatos 2025 + film + paper port

Base: v1.8.14 Build39 `f5b207e5ce20e924e97fc0c1f196df6eb4c43869`; Apple A15 passed existing 8/8 numerical diagnostic, 24-source positive scanner RGB pairs, 18 negative print pairs, and 18 negative log exposure H-D/nonspatial DIR print RGB pairs. User reports paper EV works with camera compensation disabled; original compensation formula is **not altered** here.

## Actual changes (one coherent algorithm batch)

1. **Original Float64 Hanatos LUT for all 20 measured filming stocks.** Existing Python generator `generate_hanatos.py` integrates upstream `irradiance_xy_tc.npy` against each stock's measured spectral sensitivity and original erf4 UV/IR adaptation window. It now creates `GeneratedHanatosPreciseData.swift` containing 20 source-contracted original **IEEE754 Float64 response arrays** (little endian), in addition to its previous lightweight Float16 mobile Swift source file. The pre-integrated upstream source is Float64; this does not certify whole-image Float64 intermediates in Core Image/Metal. Matrices and LUT SHA must match, and precise-mode missing data causes an exception, never silent fallback.
2. **Explicit precision selector in native app**: `Hanatos 原版 Float64` on (original stored doubles, no Float16 quantization) / off (previous faster packed Float16). Same reflected Mitchell kernel is used in both. Default on in v1.8.15; selector goes through normal LUT rendering, separate density grain production path, and spatial DIR generation. UI wheel/floating preview and export unchanged. The mode is currently backed by original Float64 LUT but the final image LUT/metal resources may still be Float32.
3. **Source exact camera EV ordering**: source FilmingStage.expose multiplies raw film irradiance by `2**camera_ev` before applying `log10(fmax(raw,0)+1e-10)`. Production Swift now centralizes the same order and uses it in both ordinary and spatial DIR pre-exposure. This corrects an old difference near black rather than approximating it.
4. **New source-contiguous 13-stage test from linear RGB camera input:** Python generator extracts and **runs original AST function definitions** `_rgb_to_tc_b` and `rgb_to_raw_hanatos2025` from upstream `spectral_upsampling.py`, and imports the real upstream `apply_lut_cubic_2d` from `fast_interp_lut.py`. It uses source Float64 TC LUT and original stock sensitivity/adaptation. Original upstream `density_curves.py` and `couplers.py` produce film measured H-D and nonspatial DIR; source NumPy optical printing, s023 CDF paper and ACES scanner produce downstream references. 6 source routes x 4 linear RGB colors = **24 vectors / 72 channels**. Independent camera EV `0,-1,+1,+0.5`, paper EV, CMY filters, preflash and various developer morphology cases are included.
5. **13 stages ×72 channels on macOS CI and separately on iPhone:** 1) Hanatos camera raw, 2) source camera EV log exposure, 3) measured negative H-D, 4) DIR inhibited exposure, 5) negative post-DIR CMY, 6) optical enlarger, 7) print log exposure, 8) source absolute paper CDF H-D, 9) XYZ, 10) linear sRGB, 11) ACES RGC, 12) encoded sRGB, 13) actual **production render() including encoded input CCTF decoding**. All use native production Swift functions. Both precise Float64 and fast Float16 modes report MAE/RMSE/max and each-stage >0.002 counts. The **original Float64** path must have 0 exceeded channels in all 13 stages; mobile Float16 deviations are recorded honestly as quantization approximation and never used for precise-mode certification.

## Boundaries and release gate

This is a **single-pixel/per-sample** reference through the complete **nonspatial** optical chain, starting from decoded RGB (not sensor mosaic camera RAW). It does not cover autoexposure, full image/edges, spatial DIR, diffusion/halation, scattered light, random Numba grain threads, RAW decode, output JPEG. The regenerated source LUT is stored as Float64 but the final Core Image 3D LUT remains Float32 for photo output. Full original image and RNG certification remains intentionally blocked by the existing strict final gate; successful numerical tests/unsigned IPA publish do not imply the overall CI conclusion succeeds.

iPhone: install signed experimental IPA Build40, import an image, switch Hanatos precision on/off to observe speed/preview behaviour, and run existing `检测本机 Metal 显影内核` to copy appendix `原版 Hanatos Float64→负片 DIR→相纸→RGB`. Compare both precision modes against source Python vectors. Existing 8/8 count stays unchanged. The original shooting compensation controls are intentionally untouched.
