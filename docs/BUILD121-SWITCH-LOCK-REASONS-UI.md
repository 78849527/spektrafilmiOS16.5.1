# Build121｜开关关闭/锁定说明与叹号交互｜iOS16.5.1

## 对照问题
Build120 真机截图：Kodachrome 64 反转片、快速/精细冲印下，开关轨道为灰色时无法区分“当前关闭”“原版算法要求开启且锁定”“欠缺前置条件”“照片处理中暂不可用”。用户要求每个关闭或锁定的开关下显示原因／所需模式，右边提供可点的叹号查看详细说明。

## 实现
- 工艺四阶段、调整（质感/细节）的 `resetToggle`，及 `simpleToggle`、`sourceModeControl`，统一使用 `switchGuidance`、`switchInfoButton`。
- **正常开启且可操作**：不额外占高度。**正常关闭**：正文下方显示「当前关闭 · 点击开关即可开启」，右边有独立 `!` 图标；点图标只解释参数用途，不代替用户打开开关。**开启但强制锁定**：显示「已开启并锁定」与完整依赖原因。**关闭且锁定**：显示「当前不可操作」、缺少的模式或前置条件，以及相应操作路径。
- 点击 **!** 使用独立 Alert 说明，不改变设置，也不自动跳到其他处理模式或关闭冲突项；覆盖真实照片未加载、模型忙、DIR/FIR-YVV、8-bit、Float64、摄影镜头、s023、原版放大机、光谱扫描、快速随机颗粒、扫描锐化、Poisson 等依赖。
- 重构共用行：旧逻辑 `.disabled(!enabled)` 曾锁住整行；现只禁用**真实开关 Button**，! 作为同级独立 Button 保持可点。旧的 `requestSourceMode` 依赖确认仍完整保留；无自动升级/近似兜底。
- **精细冲印 → 调整 → 质感**：原来展示旧版快颗粒灰色开关，改为绑定已有 `sourcePhysicalGrainEnabled` 的原版三亚层颗粒；与「工艺 → 胶片」同一 ObservableObject 参数，不引入重复业务模型。快速处理下仍展示原本的快速颗粒开关。
- 开关轨道仍旧 28×16、点击区域与主编辑悬浮区高度不变；只有当前阶段内容区内部滚动增加一条说明，不移动图片容器。
- 对于 Kodachrome 64 反转片，相纸阶段仍隐藏，扫描直通；精细冲印强制依赖原版扫描的开关仍不可直接关闭。

## 边界
仅修改 SwiftUI、审计脚本、版本及 CI。**不修改**：Python 原版数值基线、Swift/Metal 处理引擎、默认值、随机数、LUT、自动验证标准、RAW/ICC 链路、13MP 内存门槛、导出格式、光学流程；Build119 已认证的 13MP 基础两路线证据仍为 Build119 的真机证据。

## 验收
通过三种开关源码审计及 iPhoneOS16.5.1 arm64 完整编译，原版 Python 颗粒和光谱数值回归。IPA 为未签名；通过源码审计不能证明独立 ! 图标真机可点，须真机手测至少锁定已开启的“胶片层间扩散/光谱扫描”、缺前置条件的“摄影柔化/8-bit DIR”以及可用关闭的“原版三亚层颗粒/扫描镜头与锐化”。
