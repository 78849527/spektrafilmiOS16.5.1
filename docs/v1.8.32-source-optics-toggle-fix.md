# SpektraFilm v1.8.32 Build 57 — full-physical source switch routing bugfix

## Screenshot root cause
v1.8.31 emitted '原版像素直连当前不支持光晕/散射...' while the
user had enabled the prominent '乳剂散射' old CI switch, despite
the existence of the new separate original Double scatter/halation
engine. The v1.8.31 guard tested spatialSettings.enabled without
distinguishing ordinary direct-DIR and full-physical source modes.

## Changes
- The familiar '乳剂散射' and '背反射光晕' toggles retain their
  original mobile behavior outside full-physical mode.
- In explicit 8-bit pixel-direct + full-physical mode the same two
  toggles invoke the original Python model.diffusion.apply_halation_um
  Double source engine; no Core Image rendering or silent fallback.
- Plain direct-DIR with full physical OFF still rejects unsupported
  scatter/halation. Full-physical mode still rejects stochastic
  density grain and old CI scanner finishing.
- The separate v1.8.31 combined original source toggle remains
  available and has priority for its independently adjustable strength.
- Native Swift regression tests cover none/scatter-only/halation-only/
  both/combined switch matrices and source Settings.validate().
- Memory preflight includes the new exact source 120 bytes/pixel
  estimate also when either of the familiar toggles enables source optics.
- Retain iOS 16.5.1, both film/paper wheels, true original source
  Float64 FIR/YVV optical processing, existing source numeric tests
  and explicit 12MP full-size export cap.

## Real-device acceptance
1. Test a JPEG <= 12MP in full-physical source mode. With both common
   switches OFF, verify unchanged v1.8.31 preview.
2. Turn on '乳剂散射 · 原版 Double' ONLY: preview should complete
   with zero modal error and physically plausible high-light scatter.
3. Turn it off, turn on '背反射光晕 · 原版 Double' ONLY: original
   source three-bounce halos only. Then test both simultaneously.
4. Export original-size to Photos after confirming RAM budget. No
   8-bit direct-DIR Core Image fallback.
5. With full physical OFF but direct-DIR ON, requesting the old
   scatter or halation must still fail explicitly, as source does not
   support it in that path.
6. The screenshot shows 7728×5152 (~39.8MP). That is above the
   existing 12MP physical memory / size cap; small preview may pass,
   original-size export must reject clearly. Do not claim 40MP support.

## Certification limits
Source Python->Swift numerical fixtures and iOS compile must pass
separately. Random Numba stream, full RAW, and true original
end-to-end iPhone 40MP image fidelity are NOT certified.
