# SpektraFilm iOS 16.5.1 v1.8.30 Build 55 — Source Python camera-stage batch

## Batch of THREE interconnected source modules

The previous v1.8.29 professional NextLevel still camera, RAW DNG original
storage, JPEG companion print, floating image preview and manual capture
controls remain unchanged. This release resumes the **pre-camera** original
Python SpektraFilm algorithm port, in one cohesive opt-in batch:

1. **Original FilmingStage.auto_exposure — seven meter algorithms.**
   `average`, `median`, `center_weighted`, `partial`,
   `matrix`, `multi_zone`, `highlight_weighted`, plus `off`.
   Uses Python `colour.RGB_to_XYZ(..., 'sRGB', apply_cctf_decoding=True)`
   luminance, the source long-edge normalized image geometry, 5×5 matrix,
   3 concentric masks, Y² high-light weighting and original 18.4% gray.
   Applies multiplier `2**ev` to **encoded RGB before Hanatos** and
   performs source nearest-neighbour 256-pixel exposure-meter preview.
2. **Original numba_boost_hightlights.boost_highlights.** The true
   full-frame RAW-photon maximum, protected threshold, exponential ratio
   and boost formula in Double precision, after film exposure compensation.
   Cannot be approximated by a display gamma/tone slider. Source boost
   is default zero (does not alter previous output).
3. **Original camera lens apply_gaussian_blur_um.** Source film-plane
   `sigma_px=lens_blur_um/(film_format_mm*1000/max(width,height))`,
   applied to full-resolution linear RAW photons BEFORE film H-D and
   spatial DIR. Reuses validated full-image source reflect FIR (<3 px)
   or Young–van Vliet IIR (>=3px) without Core Image, Float16, tiling or
   a fabricated 3D LUT.

Production source ordering when opted in:
`sRGB ImageIO Double → optional original auto-meter RGB EV → Hanatos Float64
→ film EV in RAW photons → original Numba-formula highlight boost → source
FIR/YVV lens blur → log10(positive RAW+1e-10) → source H-D → spatial DIR
→ print H-D → spectral scanner → optionally source scanner blur/unsharp.`

All three module controls are under the **8-bit 原版像素直连 →
逐像素全光学 → 原版摄影曝光前处理（Double｜三模块）** area. They are disabled
by default; the old v1.8.29 original physical path is unchanged unless
explicitly activated. The current physical-file ingress remains strict 8-bit
sRGB. Neither DNG decoding nor high-bit-depth input is claimed here.

## Numerical evidence and explicit limitations

`ios/scripts/generate_source_camera_batch.py` calls **real upstream**
Python functions and emits runtime-independent Float64 source references:
7 modes × 2 image sizes (includes 256-edge nearest preview), plus three
source black/white metering edge images (including black-frame infinity
recovery); 3 full RAW Numba highlight images (including boost=0 identity);
4 full-size source Gaussian RGB images (including sigma=0 identity and the
exact sigma=3 FIR/YVV dispatcher boundary). `OriginalSourceCameraBatchValidation` evaluates native Swift
against these numeric references; failure blocks the iOS build.
Also tests no-effect camera RAW/H-D path vs old path at 0.5 EV.

The experiment is NOT certified as complete Numba stochastic grain, UV/IR
per-wavelength sensitivity filter, film scatter/halation, original diffusion
filter, print diffusion, scanner stochastic glare or camera Bayer DNG RAW
development. Do not silently switch to mobile preview on source errors.

## iPhone A15 physical acceptance checklist

1. Leave the new camera pre-film toggle OFF; photograph/import the same
   8-bit sRGB JPEG as v1.8.29, check previous preview and film/paper.
2. For source mode: select **Hanatos Float64**, **原版扫描 ACES**,
   **原版 DIR FIR/YVV**, **8-bit 原版像素直连**, **逐像素全光学** and
   original optical enlarger for negative. Keep CAM16/black-white reference,
   stochastic grain, scanner mobile finishing, scatter/halation OFF.
3. Turn the **原版摄影曝光前处理** switch ON. Set
   `center_weighted`, boost EV 0, lens μm 0. Compare preview with OFF.
   Observe how non-uniform images change exposure. Test other six methods
   individually, especially bright window vs dark corners.
4. Highlight recovery: set boost EV 1.0 → 2.0, spread 0.3,
   protect 4. Confirm bright lamp/sky changes, shadow neutral areas stay
   almost unchanged. Return to 0 and confirm the result reverses.
5. Lens: set 0 → 15μm → 35μm; confirm real optical light-source
   softness, correct edges and image geometry. Switch OFF should return
   to the legacy source result.
6. Export a 1200×800 photo at original size in source physical mode and
   another actual 10MP photo only when memory safety budget permits;
   verify JPEG dimensions and Photos save. Any memory error must be explicit
   and must not silently resize or switch algorithms.
7. Return to camera: test JPEG/HEIC capture→direct print, selected
   film/paper preserved, and DNG+JPEG capture if the camera truly exposes
   RAW support (the DNG must remain separate).
8. Rerun real-device original Metal 8/8 diagnostic; this release's
   Python references and xcodebuild do NOT certify Numba threads,
   entire final Float64 RGB image or real-device RAW processing.
