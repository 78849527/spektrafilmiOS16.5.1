# SpektraFilm iOS 16.5.1 — v1.8.26 Build 51

## Batch port: original deterministic scanner lens and Unsharp

The user verified v1.8.24's 3888×2592 full physical JPEG export and
v1.8.25 now passes all 28 measured material Float64 input, 20 corrected
H-D, real 2D DIR and source full-frame optical references. This iteration
ports the **next deterministic non-stochastic two-stage scanner pipeline**
from the original Python implementation; do not silently conflate it with
the remaining stochastic scanner glare or CAM16.

**Upstream unique sources:**
- `src/spektrafilm/runtime/stages/scanning.py`:
  `ScanningStage._apply_blur_and_unsharp`, after density→XYZ→gamut,
  BEFORE `_apply_cctf_encoding`;
- `src/spektrafilm/model/diffusion.py`:
  `apply_gaussian_blur`, `apply_unsharp_mask`;
- `src/spektrafilm/utils/fast_gaussian_filter.py`:
  source 2D reflect Gaussian FIR for sigma <3.0, Young–van Vliet Double
  forward/backward horizontal→vertical IIR for sigma >=3.0.

**Actual iPhone production:**
- `SpectralPhysics.sourceSpatialScanLinear()` exposes true pre-CCTF,
  pre-finishing ACES linear RGB values directly, without an intermediate
  encode/decode cycle or a 3D colour cube.
- New `OriginalSourceScannerOptics.applyInPlace` applies original full
  spatial Gaussian lens blur, THEN source `rgb +
  unsharpAmount * (rgb - gaussian(rgb, sigma))`, with Double full-frame
  reflect FIR / YVV from the previously Python-verified production path.
- Finally apply original sRGB CCTF encoding. Source stage may retain
  temporary out-of-gamut Double values until the display JPEG 8-bit clamp.
  Do not blur *already encoded* sRGB, change scanner order, substitute CI
  Gaussian, or change source boundary conditions.
- Separate experimental controls: lens sigma / pixels, unsharp sigma /
  pixels, and unsharp amount. Each adjustable parameter preserves
  click-numeric/double-click-name reset semantics. This mode defaults OFF
  even if the user had old `扫描锐化 / 微眩光` enabled.
- Preserve separately the old scannerFinishingEnabled CoreImage approximate
  routine, which still includes stochastic glare and is prohibited in
  true source optical mode. This iteration NEVER claims that random glare
  or whole source RNG has been ported.

**Performance/safety:**
- Existing full source original 12MP max, strict iOS physical/process
  memory preflight, and normal source 16MP DIR are preserved.
- Enabling scanner optics explicitly adds 40 estimated bytes per pixel to
  the original 120 B/pixel budget for the extra spatial Double workspace.
  Some previously admissible 10MP images will be refused WITH scanner
  optics enabled; disabling it restores previous validated 10MP export.
  This is an honest memory gate, not an implicit resize or algorithm swap.

## Numerical evidence, independent original Python

Generate `ios/verification/generated-scanner-optics-v1.8.26` by running
`ios/scripts/generate_source_scanner_optics.py`: load the actual source
`fast_gaussian_filter` function from its source file and execute eight
independent 2D linear RGB inputs. Cases cover identity, FIR→FIR,
IIR→FIR, FIR→IIR, IIR→IIR, exact sigma=3 boundary, 1-column and 2-pixel
frames. Store **original Float64 bytes with SHA256 for each stage**.
The Swift CI runs `OriginalSourceScannerOptics.applyInPlace` (real app
production), computes abs max/MAE and exact geometry, and requires
abs max <=3e-10 and MAE <=1e-11 for every full image and stage. No CI
generated frame is sourced from Swift. Existing non-scanner seven-stage
Hanatos/H-D/DIR/paper/ACES image parity remains unchanged and mandatory.
