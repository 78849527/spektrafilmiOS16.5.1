# SpektraFilm iOS v1.8.10 — original scanner NaN wavelengths

## Upstream behavior and defect

The original `compute_density_spectral` propagates a missing CMY dye or base value as NaN at that wavelength. The original `density_to_light` converts that NaN transmission to **ZERO light**, not zero optical density. The native iOS v1.8.9 packed all missing spectral entries as Float32 zeros, then incorrectly integrated those wavelengths as if the source film had no dye absorption.

## Change and regression evidence

- Generate an 81-byte wavelength-validity mask for **all 28** original measured stocks, retaining the existing Float32 packed measured data and the corresponding original SHA.
- Decode masks strictly in native Swift (invalid masks throw errors, not fallback). Skip invalid wavelengths in the original production scanner XYZ sum, reference white weights, and the legacy scanLinear integral.
- Independent Python source regression checks each generated mask against original measured NaNs and proves equivalence to the upstream zero-light behavior on three positive-stock densities (2 stocks).
- Swift 24 source positive-film cases × 3 output channels still report independent XYZ, linear sRGB, ACES RGC and encoded sRGB errors; new native regression rejects any final encoded channel >0.002.
- Preserve native Metal particle/IIR algorithms, preview, film/paper wheel, parameter reset, original high-resolution output and Photos saving.

## Strict status

Only direct positive-film scanner stage-scoped RGB is evaluated (and optional ACES RGC, not default CAM16). RAW/negative/print/grain stochastic state/full-image/JPEG equivalence remains unverified. User-provided Apple A15 **v1.8.9** 8/8 report does not certify the v1.8.10 build. Github macOS Paravirtual Metal failures require independent real-device testing. Unsigned IPA needs signing and is experimental.
