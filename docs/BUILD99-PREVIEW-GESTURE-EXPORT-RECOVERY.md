# Build99｜正式化专项：连续拨轮、预览一致性、手势与导出阻断

基线：Build98 完整 iPhoneOS Release PASS（`c2947d77f868d0fd3cfb1fef82419daf8c2b97fc`）。
版本：`1.8.66 Build99`，最低 iOS 16.5 不变。

## 已实施

1. **胶片与相纸连续切换**：拨轮发起的新光谱计算立即将旧预览标记为过期；显示原片，禁止让旧 LUT 冒充新胶片。包含 380ms 防抖与 generation 最新结果准入。
2. **失败保持 fail-closed**：当前胶片/相纸 LUT 重新生成失败或旧轮次先返回时，导出保持锁定并报告具体错误。JPEG、TIFF16、精确模式导出均校验最新状态，不能使用旧 LUT 继续。
3. **光谱阶段事务保护**：只在 LUT、DIR、密度颗粒配置齐备且预览合法后提交。若新 LUT 刷新同步失败，恢复 LUT、DIR、密度颗粒、strength，废弃晚返回的图像，禁止将新参数和旧数据混用。
4. **防止旧任务卡死 Busy**：替换照片／取消当前源任务时，释放属于已废弃的光谱会话的 busy 标记；延迟返回的旧任务不得覆盖新照片。
5. **普通移动预览的错误反馈**：同步 Core Image 胶片模拟抛错时，清空旧处理预览并明确显示原图，不再让用户误以为旧照片是新设置的成功结果。
6. **同尺寸换图手势复位**：`photoSessionRevision` 在真正成功提交照片后自增，即使新旧尺寸相同也会重置双击放大、长按原片状态、分屏和拖动位置，同时清理旧快速模式参数快照。
7. **分屏手势冲突**：将比较图拖动的 `DragGesture(minimumDistance:0)` 改为最小 8pt 的意图拖动，同时提供独立双击放大／复原；复用同一缩放规则，并对无效坐标和极端比例钳制。

## 验证

- macOS 真正执行 `Build99InteractionRulesValidation.swift`，验证 12 项界面规则（双击缩放、分屏钳制、旧 generation 拒绝、失败/待计算 LUT 导出锁定）。
- `build99_preview_export_audit.py` 继承 Build98/97/96/92 原有检查，新增 15 条生产调用路径门禁。
- 严格保留 Python 原版生成的 48 份 12 阶段数值参考审计、LibRaw arm64、UInt16 TIFF IFD、RGB48 以及 Build97 Core Image 故障注入。
- 仅在 `xcodebuild -sdk iphoneos` 原生 arm64 Release 成功与 ZIP/IPA SHA 核验后发布未签名实验 IPA。

## 限制与真机验收要求

本批**不是**原版精度完整认证，也不是 iOS 16.5.1 真机操作证据。需要用户在真实设备实测：
- 长按原片与双击缩放/分屏拖动是否不冲突、同尺寸照片连续替换；
- 连续 30 次胶片/相纸拨轮，模拟失败后安全导出阻断、切换回有效配方后可恢复；
- 低内存/大图 JPEG、TIFF16 连续导出，失败后继续编辑；
- 原版 Python Float64 单张整图阶段/输出实测；未认证模块必须保留实验标记。

富士 X-T5 额外研发暂停；此前已移植的 LibRaw 与高位深 TIFF 保留。全部上游原版光学、随机、色彩算法未作改写。
