# SpektraFilm iOS v1.8.23 Build 48 — original-size export preflight

## User-reported defect

A 3888 × 2592 photograph (10,077,696 pixels) correctly exported
in existing 8-bit `原版像素直连` mode, but enabling the experimental
`逐像素全光学` mode caused this misleading error:

> 原版像素直连超出当前内存安全范围（最大 1600 万像素）

The photograph does NOT exceed 16 MP. Source code passed the experimental
mode's **2,000,000** maximum to the shared ImageIO decoder, but its
error message was hard-coded to **16,000,000**. The export confirmation
sheet additionally used the general CoreImage memory plan, so it could
display the original size as "confirmable" before the stricter 2MP source
physical path rejected it at export.

## Production fix

- `OriginalSourcePixelIO.validatePixelDimensions` uses the actual selected
  limit and reports actual unrotated source pixel width and height, million
  pixel count, the side cap 8192, and selected precision mode. No hard-coded
  claim that 10MP exceeds 16MP.
- `OriginalSourcePixelIO.preflightExport` obtains actual width and height
  **directly from original file ImageIO metadata** using
  `kCGImageSourceShouldCache:false`, before decoding a full CGImage.
  The same mode-specific validation is then used for the full-size decoder.
- `PhotoEditorModel.prepareExport` validates the chosen precision mode
  **before showing the export confirmation sheet**:
  - legacy user-tested 8-bit source-pixel DIR: original image <=16MP;
  - new nonlinear per-pixel Hanatos/H-D/spatial DIR/paper/scan:
    original image <=2MP (temporary strict device-memory safeguard).
  Both preserve original pixels and refuse unsupported combinations without
  quiet image resizing, alternative shaders or CoreImage fallback.
- Preview remains explicitly downsampled, but never authorizes full export
  beyond its actual source mode's limit.
- The 2MP experimental optical limit is a conservative software memory
  guard for several simultaneous full-size Double RGB stages and spectral
  calculations, not a limit of the user's iPhone or the original Python.
  Raising it safely requires new whole-image memory architecture / empirical
  hardware benchmarks, not deleting the guard.

## Regression

Original ImageIO 3x2 PNG encode/decode verifies metadata preflight.
Additional native regression cases:
- 3888 × 2592 (10,077,696 pixels): **accepted** by 16MP direct DIR;
  **rejected** by 2MP physical optics, with an honest message naming
  both the requested geometry and the 200万 threshold.
- Exactly 4000 × 4000: accepted by 16MP DIR mode.
- 4001 × 4000: rejected by 16MP mode.
- Exactly 1600 × 1250: accepted by 2MP physical mode.
- Existing independent upstream Python three-frame nonlinear seven-stage
  optical comparisons, v1.8.20 exact DIR image regression, original
  film/paper/scanner and Poisson/MT/Numba scalar tests remain unchanged.

## Scope/verification

This is **not** a claim that full nonlinear optics now supports 10MP;
the existing validated 10MP source-DIR output remains unchanged.
No stochastic full Numba RNG, ProRAW/RAW, high bit depth, source CAM16 or
complete real-iPhone Metal Float64 certification is claimed. Publish
only experimental `UNVERIFIED-TEST` unsigned IPA with the previous strict
certification gate retained.
