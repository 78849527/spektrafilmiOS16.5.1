# v1.8.7 — 智能安全分辨率和源 Numba 微结构公式

## 用户验收标准

iOS 16.5.1。顶部存相册／分享文件入口均保留原图图标和操作位置，点击后现在可以选择：

1. **原始分辨率**：不主动缩小，失败给出明确错误，不隐式转其他模式。
2. **智能安全分辨率**：按低于设备物理内存三分之一、至多 1500MB，以及 Apple 当前进程可分配内存中的**更小者**确定预算，仅使用预算的 50%，按 104 B/像素的保守估算计算目标。无 300 万像素硬上限；1500MB 对应约 720 万像素，但实际机型总物理内存和当前剩余进程限额可能更低。
3. **省内存分辨率**：保留 v1.8.6 最高 300 万像素上限，再以同一当前预算的 30% 约束。
   
三档都在 **开始导出前显示预估原图宽高、目标宽高、估计峰值、设备预算、当前 App 内存余量**，需用户再次明确确认。确认的像素尺寸被传给后台导出，若实际内存已经下降则清楚提示重新确认，**不能**无提示地再缩小。滤波在 Core Image 源输入阶段对完整图执行 Lanczos，不允许将 SciPy 每通道 Poisson/Binomial 原版随机序列拆块重置。JPEG 质量保持 98%，保存到相册和分享文件都可用。

Apple 的 `os_proc_available_memory()` 是目前进程可再分配容量快照，绝不代表系统绝对可用内存或成功保证；它不应被缓存。若无法获取余量，按物理预算进行保守估算并明确提示未获取。瞬时设备内存压力仍有可能导致导出失败或 iOS jetsam。

## 本轮继续的原版移植

源文件：
- `src/spektrafilm/model/grain.py:add_micro_structure`
- `src/spektrafilm/utils/fast_stats.py:fast_lognormal_from_mean_std`
- `ios/SpektraFilmPort/OriginalSourceMicrostructure.swift`
- `ios/SpektraFilmPort/OriginalGrainKernels.metal`

将**微结构确定性公式和门槛**抽出为原版源兼容的生产 CPU 几何参数计算与共用 Metal lognormal helper；保留源：
- 微结构标准差 = `30nm×0.001/pixelUM`，启用 `>0.05`；
- 微结构滤波半径 = `0.2um/pixelUM`，滤波启用 `>0.4`；
- 源对数正态变换 `sigma² = ln(1 + (std/mean)²)`，`mu = ln(mean)-sigma²/2`，`value=exp(mu + sigma*z)`，实际 mean=1。
   
生成脚本以原版 Python 文本的关键数学语句和 SHA 约束生成 **5 组不同像素尺寸 ×9 个给定高斯标准值**的 Float64 参考。Swift math 逐值对照，再使用相同核心 Metal helper 对真实 iPhone GPU 输入的**给定** normals 逐像素测试（新增硬件诊断第 8 项）。上游 Numba 使用没有固定种子的并行线程随机状态，所以我们**没有**宣称 Numba 逐像素随机流可复现；GPU 生产原有 hash 正态来源仍未与上游 bitstream 对齐。

## 留待进一步移植
