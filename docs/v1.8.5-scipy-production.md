# v1.8.5 — 原版 SciPy 随机数接入生产显影（实验性）

本轮在实机验证 v1.8.4 的六项数值基线后，引入**独立、默认关闭**的「SciPy 原版随机序列」模式，不修改旧的 Metal 颗粒随机数逻辑。

## 路径和原版依据

源码唯一依据：`src/spektrafilm/model/grain.py:layer_particle_model`、`apply_grain_to_density_layers`。其中每种颜色、每个三乳剂亚层重置 `np.random.seed(ch + 10*sl)`，随后先生成整幅 Poisson seeds 数组，再生成整幅 Binomial development 数组。

生产路径：`OriginalSourceSciPyParticles.renderLayer` 按行优先次序从 GPU 读取一个完整乳剂层通道（Float32），Swift `OriginalSourceSciPySampler` 用经独立数值测试的 NumPy MT19937、Poisson/PTRS、Binomial 反演/BTPE 顺序产生原版两阶段颗粒计数。用源物理系数和 Double 计算 `Double(count)*odParticle*saturation` 后写入线性共享 RGBA32Float 纹理。该纹理交给原有经过 iPhone A15 实测的整幅 FIR/YVV、逐亚层累加、微结构和最终扫描链。

**必须走整图处理**，不得把 512px tile 当作随机数种子重置边界。通道读回仅分配每像素一个 Float32，Poisson 种子数组使用 UInt32（溢出失败，而非截断）。每个亚层逐个执行、完成 GPU 命令后回收；保留内存预算及 GPU Float32。大图可能耗时较长；若超出安全预算，明确停止，不回落至近似路径。

## 认证边界

- **已通过的独立来源测试**：v1.8.3 NumPy MT19937 2640 UInt32 / 160 Double、SciPy Poisson→Binomial 5 组 631 像素计数及抽样后 MT 字、v1.8.4 原版九路随机场回放。新生产接入新增 **第 7 项实机检查**：GPU 读取的输入通过 Swift SciPy 两阶段采样形成粒子密度，直接与 Python 原版同一基准图每像素对照。
- **仍不能宣称完整数值同一**：原版 Python 的 CIE/NumPy 处理及中间 64-bit 光学密度在 iOS CoreImage 入口已变为 Float32，因而某些临界 RNG 分支可能与纯 Python 不同；原版 Numba 的微结构随机状态仍未移植；最终 RAW→纸张→扫描 RGB 的像素、RMSE/MAE、DeltaE 端到端尚未完成。
- **生产模式互不覆盖**：开关默认关闭；v1.8.4 已验收的 Metal 哈希颗粒模式仍保留。源 SciPy 只在「密度颗粒 → 实测三乳剂亚层 → 原版 Metal 显影链 → SciPy 原版随机序列」四项同时开启时调用。旧模式不变。
- **实机验收要求**：第 7 项 CPU→Metal 颗粒密度对照通过，应用不崩溃，原图/效果悬浮预览不阻塞主线程，保存原分辨率 JPEG 到相册；还要观察原版随机模式的实际运行时间和峰值内存，不能只靠小图测试判断高清性能。

该版本维持 TEST/UNVERIFIED 标签，不使用完整认证发布标签。
