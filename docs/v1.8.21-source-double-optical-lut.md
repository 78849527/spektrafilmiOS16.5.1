# SpektraFilm iOS 16.5.1 v1.8.21 — Double nonlinear optical LUT nodes in production source spatial DIR

## Actual production change

v1.8.20 proved only an **identity optical LUT** + upstream source FIR/YVV
spatial DIR whole-frame numerical comparison (three nonuniform 8-bit sRGB
images, 871422 RGB components, eight stages); that fixture does NOT prove the
real film-H-D, paper-CDF and scanner colour chain.

v1.8.21 removes an identified extra **Float64→Float32 LUT-node quantization**
from the *real* production DIR precision path:

- `SpectralPhysics.makeSpatialDIRStageData` retains Double computed
  Hanatos camera log exposure, measured film initial H-D, source pre-DIR
  corrected H-D and nonlinear film-density→paper→scanner output node values.
- `SpectralPhysics.makeDensityStageData` calculates print RGB once per
  three-dimensional LUT lattice point and stores BOTH the original Double
  result and a separate Float32 packing for the existing fast/CoreImage path.
- `SourceSpatialDIRConvolution.applyExactImagePath` consumes only the Double
  four-cube node arrays and applies Double trilinear interpolation and original
  Double spatial FIR/YVV. A missing or invalid Double node array is a hard
  error, NOT a reason to silently use the packed mobile LUT.
- Mobile CI fast rendering continues to use the old Float32 cube and has
  no numerical or UI behavior change.
- Preserve exact 8-bit sRGB ImageIO → Double spatial DIR → JPEG and all
  v1.8.20 import, photo-library, floating preview, two-wheel and reset paths.

This genuinely changes source-mode output, albeit potentially by less than one
8-bit output code. It retains **full nonlinearity of computed LUT lattice
values**, not a per-pixel film-spectrum inversion, and can still differ from
the upstream original Python for off-grid RGB inputs because a 9/17/33
interpolated 3D LUT is not the original direct physical per-pixel operation.
Also, the measured spectral/H-D tables were previously stored as Float32;
keeping Double *after* the measurement-table decode does not restore
missing original source Float64 measurement bits.

## Regression checks

- Existing 3 nonuniform real Python upstream DIR image samples continue to
  run with explicit exact Double identity cubes at the image-stage boundary.
- New real nonlinear Kodak Portra 400 → Kodak Portra Endura source optical
  stage (9³ source/print and 17³ corrected nodes) validates all four Double
  arrays against their Float32 packed mobile representations. It reports
  exact number of nodes altered by rounding and maximum quantization.
- Existing direct Python-source film H-D/DIR/print/scanner and 13-stage
  Hanatos reference checks remain mandatory; real nonlinear LUT test is
  an additional production-node integrity test, not a replacement.
- Explicit missing-double-node negative test must throw rather than render.
- Retain the original iPhoneOS build, iOS 16.5 minimum and fail-closed
  `verify_precision_release.py` as-is.

## Still not certified

- End-to-end original Python Float64 **full physical nonlinear image** parity;
  all measured profile source Float64 coefficients, exact continuous spectral
  photo inversion rather than trilinear optical LUT sampling;
- Source Numba prange/thread random streams; physical grain/dye-cloud and
  microstructure full-image pixels; RAW/ProRAW/high bit depth;
- Halation and post-scanner gamut/finishing ordering; physical iPhone
  Metal full-frame RGB/CMY, deltaE, edge/tile, memory/peak image export
  certification.

These items remain `近似实现` or `尚未移植` and are never silently
promoted solely because the CI numeric suite passes.
