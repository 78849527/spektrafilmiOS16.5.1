## Source and execution scope

Implemented in production physical camera photon-domain (opt-in):
\`FilmingStage.expose\`: decoded RGB → source RGB exposure meter → camera
spectral RAW → camera EV → highlight boost → **camera diffusion PSF**
→ Gaussian lens blur → film scatter/halation → log10 → H-D/DIR.

The source diffusion kernel is *not* a generic Gaussian blur or Core Image bloom:
- Families: Glimmerglass, Black Pro-Mist, Pro-Mist, CineBloom, with original
  per-group core/halo/bloom lambda, geometric subcomponent grids, power-law
  bloom weights, family strength gains and scatter-fraction breakpoints.
- Per-channel energy-conserving halo warmth axis (+1.30,+0.15,-1.45),
  normalized channel PSFs and all 6 original overrides.
- Source formula \`(1-p_s)*raw + p_s*blurred\`, with original image-wide
  NumPy reflect padding, large/full PSF and same-convolution crop.
- FFT operation uses native radix-2 **Double** transforms, not a CI or
  Metal Float32 shader. Intermediate precision and float operation order
  differ from SciPy FFT implementation; test full-image difference by
  numeric tolerance rather than asserting bitwise equivalence.
- Disabled by default; all existing image, film, paper, DIR, UI and export
  values must remain unchanged unless the user explicitly enables it.

REAL production Swift source with \`xcrun swiftc\`, then selects and
compiles EXACT ORIGINAL Python AST nodes from the pinned blob without

Covers four original filter families, different commercial strengths,
halo warmth, channel overrides, varied rectangular frame shapes, radius
clipping, per-channel PSF normalization, source reflect boundary and

## Constrained memory and accuracy status

The native code estimates the required complex Double FFT grid BEFORE
allocating full PSF. Above 512 MB allocated FFT working-set estimate or
an unsupported FFT dimension, it raises a clear error. It does NOT cut
the original PSF, alter boundary mode, silently substitute FIR/CI blur,
scale down the image, or change the global scientific certification guard.
The broader phone/source memory preflight remains in place.

This is a complete source **camera diffusion algorithm implementation** at
the level of optical formula/controls/source order, with limited
stage-scoped native numerical verification. Do not mark it as fully
certified source iPhone imagery or complete all-module Float64 parity.
Large full-size 12MP camera diffusion may be disallowed by source memory.
