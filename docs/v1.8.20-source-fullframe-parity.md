# SpektraFilm iOS 16.5.1 v1.8.20 — SOURCE spatial DIR whole-frame parity gate

## What changed

This version retains the user-confirmed **v1.8.19 iPhone functional behavior**:
opaque 8-bit tagged sRGB input → ImageIO native pixels → Double production
spatial FIR/YVV DIR → no CI pixel bridge → original-size JPEG.
The non-original paths still fail closed when precise input/output is requested.

**New evidence is restricted to the spatial-DIR stage.** The macOS CI job
generates **fresh** Python Float64 truth by importing and executing upstream
`src/spektrafilm/model/couplers.py` and source
`src/spektrafilm/utils/fast_gaussian_filter.py`, with original
positive/negative film donor/receiver matrices and 20/200 μm source
Gaussian/exponential FIR/YVV routes.

Three deliberately nonuniform 8-bit tagged-sRGB test images, not photos,
are encoded by the Python test generator: negative 193×129, positive
192×128, and negative 601×401. Each contains high-frequency, edge and
separate-channel signals to expose row flips, per-channel swaps, precision
changes and boundary deviations. The images are regenerated at build time,
not stored as claimed proof in the repository.

The production Swift test then:

1. Reads the PNG with **the real** `OriginalSourcePixelIO.decode` ImageIO
   ingress, rejects invalid ICC or unexpected coordinates, and compares all
   original RGB channels against Python Float64 source values.
2. Constructs an identity optical LUT and **measured original DIR matrix**
   from the Python fixture, runs the **same**
   `SourceSpatialDIRConvolution.applyExactImagePath` production stage.
3. Compares full 2D buffers at `raw`, `initial`, `inhibitors`,
   `diffused`, `log`, `densityPreGrain`, `printed`, reporting
   **MAE, RMSE, maximum error and worst pixel/channel**, with max tolerance
   2e-5 and MAE tolerance 2e-6.
4. Separately calls the public `OriginalSourcePixelIO.develop` API and
   compares its *whole frame* Double print output, not only observer output.
5. Checks SHA256 of reference files so corrupted/swapped fixtures cannot
   be accepted as original Python truth.

All 8 stages for every pixel of all 3 test frames are evaluated. A missing
reference, invalid color tag, mismatched size, nonfinite pixel or out-of-
tolerance sample **fails the build**. CI still requires iOS 16.5 target,
same existing full iPhoneOS compilation, and distinguishes unsigned
experimental release from complete original-algorithm certification.

## Explicitly NOT certified

- The identity-LUT fixture tests DIR *stage behavior*, not actual nonlinear
  film H-D, halation, paper/spectral optics, scanner or final display RGB
  parity with Python whole-image output.
- These are 8-bit sRGB *synthetic frames*. This is not full-size photographic
  RAW/16-bit/Display P3 or real-film image parity.
- Stochastic three-layer grain, Numba multi-thread RNG ordering and
  native iPhone full-frame Metal GPU parity are NOT inferred.
- Python truth + macOS Swift comparison is NOT the same as physical iPhone
  numeric verification. The user-approved v1.8.19 functional tests do not
  certify v1.8.20 algorithm precision.

**Module states remain unchanged** until their corresponding real-source
numeric and device evidence passes. This diagnostic MUST NOT satisfy or
remove the existing strict `verify_precision_release.py` guard.

## Reproduce

GitHub Actions generates:
`ios/verification/generated-fullframe-v1.8.20/`
with a `manifest.json`, per-image `.png`, and per-stage little-endian
Float64 `.f64le` files. The native Swift `SpatialDIRValidation`
executable performs exact image input and production Double comparisons.
The CI job is the authoritative execution log; no success is claimed until
the job runs successfully.
