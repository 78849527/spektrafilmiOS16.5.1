# SpektraFilm iOS v1.8.44 Build69 — Unified menu switch appearance

## Scope

UI-only change from v1.8.43. **No original Python, Swift/Metal
simulation, numerical reference baseline, or production render mode is
modified.** iOS minimum remains 16.5 and original diagnostic report
retains the true A15 8/8 evidence boundaries.

## What changed

- All three menu levels and the independent source-mode buttons now use
  exactly one `miniatureSwitch(isOn:)` visual component.
- Visible track **28×16 pt**, white thumb **12×12 pt** with **±6 pt**
  offset. Active/inactive color remains unchanged.
- The nine third-level `resetToggle` switches previously instantiated
  iOS's large native `Toggle`; now they use the same compact custom
  component as the second-level independent switches.
- Third-level switch tap region remains accessible at **42×32 pt**.
  The label preserves the double-tap-to-default operation, and a switch
  press changes only its bound Boolean. Disabled locks and existing
  model `onChange` preview refreshes are preserved.
- Direct source-mode controls use the common 42×32 tap metric; the
  top-level feature switches already used the same 28×16 visible component.
- Avoid attaching a second gesture recognizer to the toggle button;
  retain independent label double-tap, iOS 16.5.1 type-erased adjustment
  router and deferred drawer mounting.

## Validation

1. `python3 ios/scripts/validate_unified_switches.py`: actual
   `FloatingEditorWorkspace.swift` checks shared geometry, all nine
   nested switches, second-level switches and reset/on-change
   constraints; explicitly rejects any native `Toggle()` in this UI.
2. `xcrun swiftc -frontend -parse`: actual edited view and model.
3. Full iPhoneOS Release build and unsigned experimental IPA, together
   with source optical, RNG and shader checks, run separately; **only
   the actual completed CI / Release SHA proves a build**.
4. Physical iPhone touch targets, visual alignment, menu interaction
   and screenshot/rotation regression must be verified after signing.
   Structural UI checks are not physical-device evidence.
