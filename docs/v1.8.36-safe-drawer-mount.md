# v1.8.36 Build 61 — Mitigate crash opening right adjustment drawer

## User-reported reproduction
The user installed unsigned-experimental v1.8.35 Build60 and reported:
**tapping the right-edge adjustment button immediately terminates the app**.
This is a real reported crash; no matching device .ips or symbolicated stack
was attached. Do not claim a confirmed root cause or verified device fix.

## Targeted structural correction
Previous code updated two states and simultaneously replaced the collapsed
edge tab with an entire full-width SwiftUI tree inside an animated overlay:
all feature switches, all dependent view builders and current parameter
controls were mounted at once.

The v1.8.36 patch keeps all settings/physical models and the intended
two-row UI but changes only adjustment drawer mounting:

1. Tapping "调节" first updates front-panel z-index and expanded state in
   an explicit Transaction with animations disabled. The initial panel
   contains only the header and a blank placeholder, not the full editor.
2. On the next main runloop, mount the first row of features (functions
   WITH submenus) and second row of simple switches (without submenus).
   These horizontal rows use **LazyHStack** to avoid eagerly initializing
   every off-screen toggle.
3. On the following main runloop, mount only the selected feature's
   parameter page beneath these rows. If the user closes the drawer first,
   both scheduled stages check that the drawer is still open and do nothing.
4. Closing the drawer immediately unmounts detail and row state in a
   nonanimated transaction.
5. The left film/paper drawer, bottom toolbar, top diagnostic report,
   tap-only edge tabs, open order z-index, original long-press image
   comparator, numerical reset, iOS minimum and all original image
   algorithms remain unchanged.

## Known limitations / validation criteria
- This is a defensive structural fix for a reported runtime failure, not
  proof of the exact cause.
- GitHub CI verifies the staged state guard, no full-tree animation,
  native Swift compilation and original precision tests. Passing CI is
  **not** evidence of a successful on-device open/close interaction.
- For real verification, install Build61 and exercise right edge tab,
  close button, repeated open-close, the basic/exposure page, scanning,
  DIR, paper preflash and advanced options. Check iOS 16.5.1.
- If it still terminates, obtain the actual .ips crash log (Settings →
  Privacy & Security → Analytics & Improvements → Analytics Data) and
  symbolicate the first crashing thread before additional guesswork.
- Experimental unsigned IPA needs signing; full upstream GPU/RNG/Float64
  full-image numerical certification is still independent/unverified.
